## Аудит найденной реализации

| Область | Наблюдение | Решение для Lyra 1.0 |
|---|---|---|
| Архитектура | GPT-подобный pre-LN Transformer, 12×768, 12 attention heads, tied embeddings; архитектура не реализует целевые GQA + RMSNorm + SwiGLU | Реализовать собственные модули Lyra на PyTorch, не импортируя pretrained model core или веса |
| Размер | Соседний `model.yaml` задаёт vocab 24 000 и сообщает 104 274 432 параметра | Пересчитать на целевой vocab 16 384 и целевые блоки; не переносить указанное число |
| Токенизатор | Byte-level BPE через сторонний пакет `tokenizers`; собственной модульной BPE реализации нет | Использовать `ai-forever/rugpt3small_based_on_gpt2` с Hugging Face Transformers; не обучать собственный токенизатор |
| Данные | Есть обработка, очистка, deduplication и train/val/test артефакты для русских диалогов | Разделить web-текст pretraining и качественные диалоги SFT; явно помечать неопределённые роли |
| Обучение | Есть trainer, optimizer, scheduler, checkpoint и resume-компоненты | Повторно проверить их на целевой архитектуре и на прерываниях; не считать прежние smoke-результаты доказательством |
| Проверки | В найденном отчёте smoke SFT: 4 шага, loss около 8.9, ответы 1–13 символов; это технический smoke, не оценка качества языка | Создать воспроизводимые тесты компонентов и отчёт с PASS/FAIL/NOT RUN; обучать полный run лишь после проверок |
| Веса | Есть локальный checkpoint smoke SFT в соседнем проекте | Не использовать его: старт Lyra должен быть со случайных весов |

## Расчёт целевой конфигурации

Для 12 слоёв, `d_model=768`, `d_ff=3072`, 12 Q heads и 4 KV heads (head dim 64), vocab 16 384, tied embeddings, без bias:

- Q/K/V/O в одном слое: `768×768 + 2×(256×768) + 768×768 = 1 572 864` параметра.
- SwiGLU в одном слое: `3×768×3072 = 7 077 888`.
- Две RMSNorm в слое: `2×768 = 1 536`.
- Всего блок: 8 652 288; 12 блоков: 103 827 456.
- Token embedding: `16 384×768 = 12 582 912`; финальная RMSNorm: 768.
- При HF tokenizer словаре 50 261 размер embedding равен 38 600 448; ожидаемое общее число составляет **142 428 672 параметра** при tied embeddings и bias=false. Это формульная оценка, не измерение созданной модели.
- FP32 веса такой конфигурации займут примерно 543 MiB; BF16/FP16 — примерно 272 MiB (без optimizer/активаций). AdamW состояния и активации увеличат training VRAM; фактический пик измерить только на запуске.

## План по этапам

1. **Аудит и проектирование (текущий этап).** Зафиксировать состояние workspace и соседней реализации; определить лицензии/разделение назначений корпусов; утвердить формат конфигов и интерфейсы.
2. **Токенизатор Hugging Face.** Загружать tokenizer assets `ai-forever/rugpt3small_based_on_gpt2`, добавить четыре Lyra role markers, сохранить точную ревизию и итоговый vocab size. Не загружать pretrained model weights. Проверить UTF-8 round-trip, specials, сериализацию и совместимость размера словаря.
3. **Модель.** RMSNorm, RoPE, GQA через SDPA с fallback, SwiGLU, causal mask, инициализация, tied embeddings, KV cache и генерация. Проверки формы, causal masking, backward, grad finite и параметров.
4. **Данные.** Реальные HF корпуса: web-текст для pretraining, отдельно диалоги/инструкции для SFT. Скачивание потоками или ограниченной выборкой, очистка, dedup, разбиение без утечки, manifest и лицензии.
5. **Обучение.** Устройство/VRAM диагностика, precision, accumulation, clipping, checkpoint/resume, cosine schedule, метрики и независимая validation.
6. **Интеграционные проверки.** Малый overfit run на синтетическом мини-наборе только как проверка оптимизатора/градиента, resume round-trip, генерация, CPU inference. Языковое качество оценивать отдельно на реальных данных.
7. **Kaggle.** Подготовить notebook/script с проверкой GPU, загрузкой данных и tokenizer, этапами обучения и надёжным экспортом чекпойнтов. Полный прогон начинать после локальных тестов и подтверждения бюджета/производительности.
8. **CLI, документация и отчёт.** `train.py`, терминальный чат, README, TECHNICAL_REPORT с фактическими замерами и статусом каждого теста.

## Критерий перехода между этапами

Переходить к следующему зависимому этапу только после проверки текущего: токенизатор round-trip до модели; forward/backward и causal correctness до обучения; checkpoint/resume до длинного Kaggle-run. Не подменять непроверенные результаты предполагаемыми значениями.

## Открытые риски

- Бесплатная GPU-сессия может не позволить обучить примерно 142M модель на объёме токенов, достаточном для хорошего русского языка; скорость и достижимый объём пока неизвестны.
- Hugging Face tokenizer имеет значительно больший словарь, чем первоначально заданные 16 384 токенов; размер embeddings и число параметров модели нужно считать по фактически загруженному словарю.
- Открытый workspace изначально пуст. Существующая соседняя Lyra Chat — полезный источник результатов/сравнения, но не эквивалентна целевому проекту.
